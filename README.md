# MODANICA 予約管理システム（プロトタイプ）

設計書（MODANICA_予約管理システム設計書）の内容をもとに構築した、動作確認用のプロトタイプです。
既存のWordPressサイトとは連携させず、別システムとして動かし、WordPress側からはリンクで接続する想定です。

## できること

- 施設利用プラン（1〜5）／カフェ系プラン（6〜9）の一覧・詳細表示
- 日付・人数・オプションを選んで空き状況と料金目安を確認
- 予約フォームからの仮予約送信（ステータスは全プラン「要確認」からスタート）
- プラン×リソースの排他ルールに基づく重複予約の自動ブロック
  （例：4名部屋を予約済みの日に、全館貸切プランは予約できない）
- 管理画面（`/admin`）での予約一覧確認・確定／キャンセル操作
- 料金カレンダー（`/admin/calendar`）：祝日・GW・夏休み・年末年始などの期間ごとに料金係数を設定。
  2026年の国民の祝日はあらかじめ登録済み（内閣府・国立天文台の暦要項に基づく）
  - 各ルールはその場でインライン編集（名称・期間・係数・種別）できる
  - 「翌年以降の祝日・シーズンを自動生成」ボタンで、指定した年の祝日（ハッピーマンデー・振替休日・
    国民の休日を含む）とGW・夏休み・年末年始のシーズン期間をまとめて生成できる（既存登録とは重複しない）。
    春分の日・秋分の日は天文計算による推定値のため、国立天文台の確定発表後は編集で調整してください
- プランオプション管理（`/admin/options`）：オプション（名称・価格・説明）の登録と、
  どのプランで選択できるか／デフォルトで選択済みにするかの設定
  - オプションごとに「チェックのみ（選択する／しない）」か「数量指定（個数を入力）」かを選べる。
    数量指定オプションは、予約フォームでお客様が個数を入力でき、料金は「単価×個数」で計算される
    （人数には連動しない）。最大数量の上限も設定可能
  - 数量指定オプションには単位（人・個・枚・セット・束・回、またはその他自由入力）を設定でき、
    予約フォームや管理画面の表示にそのまま使われる（例：「炭 ×2袋」「テーブル ×3台」）
- プラン詳細編集（`/admin/plans`）：プラン名・説明・料金・人数条件・受付開始タイミングの編集
  - 平日／週末・祝日それぞれについて「自動確定」「要確認」「要問い合わせ（オンライン予約不可）」を設定できる
  - 「要問い合わせ」に設定した曜日は、空き状況確認・予約送信の両方がブロックされ、
    電話・メールでの問い合わせを促すメッセージが表示される（例：週末は完全予約制で電話確認したいプラン向け）
- カフェ系プラン（飲み会・通常カフェ利用・ディナーコース/BBQプラン等）の時間指定に
  営業時間（11:00〜22:00）のバリデーションを追加
- 予約フォームに「当日の予約状況タイムライン」を表示。日付を選ぶと、そのリソース（カフェ・BBQエリア）の
  その日の予約済み時間帯が横軸で見える（他のお客様の個人情報は表示しない）。カフェ系プラン（6・7・8・9）は
  この時間軸を見ながら開始・終了時刻を自由に指定する方式
- BBQレンタルスペース貸切（プラン5）は従来通り「1部（11:00〜16:00）／2部（17:00〜22:00）／
  1日（11:00〜22:00）」の3枠から選択する方式（プラン8とは別物）。枠ごとに料金を個別設定でき
  （`/admin/plans`）、予約フォームの選択肢にも枠ごとの料金が表示される
- 収益性の高いプラン（宿泊・施設貸切）が、先に入った収益性の低いカフェ予約でブロックされにくくする仕組みを追加
  - プランごとに「最終受付期限（利用日の何日前までオンライン予約を受け付けるか）」を設定可能
    （`/admin/plans`）。空欄なら従来通り当日まで受付
  - カフェ・部分利用の予約は、競合しうる優先プラン（宿泊・施設貸切等）の最終受付期限が過ぎるまで、
    管理画面（`/admin`）で「仮予約（優先予約の受付期間中）」バッジ付きで表示される
  - 宿泊系プラン等の予約が、確定済みの排他予約とではなくカフェ予約のみと競合している場合、
    「満室」ではなく「調整可能・要相談」の案内（お電話・お問い合わせ誘導）を表示する
  - カフェ系プランの予約フォームには、日程調整をお願いする可能性がある旨・告知タイミング（2営業日前まで）・
    補償（次回使える割引クーポン）を明記した同意チェックボックスを追加。チェックしないと送信できない
- メール送信（Resend連携）：予約受付時・確定時・キャンセル時にお客様へ自動でメールを送信する。
  新規予約が入った際に運営者へ通知メールを送ることもできる（`ADMIN_NOTIFY_EMAIL`設定時）
  - `RESEND_API_KEY` が未設定の場合は実際には送信せず、内容だけ「メール送信ログ」（`/admin/mail-log`）に
    記録される「ログモード」で動作する。設定方法は下記セットアップ参照
  - 文面はいずれも `lib/emailTemplates.js` にまとまっているので、必要に応じて調整してください

## できないこと（今後の実装が必要な部分）

- 決済連携（設計書8章の通り、まずSTORESのURL決済を手動運用し、将来PAY.JPのカードトークン化APIに接続する想定。本プロトタイプには含まれていません）
- Google無料掲載連携（設計書9.3の通り、チャネルマネージャー経由での連携が前提のため、本プロトタイプの対象外です）

## 管理画面（/admin）のログイン保護

管理画面（`/admin`、`/api/admin`配下）は専用のログイン画面（`/admin/login`）で保護されています。
未ログインの状態で管理画面のURLに直接アクセスしても、ログイン画面にリダイレクトされます。
公開ページ（トップページなど）からの「管理画面」へのリンクも削除済みです。

`.env.local` に次を設定してください（`.env.local.example` 参照）。設定しないと管理画面自体が開けない仕様です。

```
ADMIN_BASIC_AUTH_USER=（好きなユーザー名）
ADMIN_BASIC_AUTH_PASSWORD=（好きなパスワード）
ADMIN_SESSION_SECRET=（推奨・ログインセッションの署名用の長いランダム文字列）
```

設定後はサーバーの再起動が必要です。ログイン状態は7日間、Cookie（`httpOnly`・`secure`）で保持されます。
管理画面右上の「ログアウト」ボタンでいつでもログアウトできます。

## セットアップ

初回のみ：

```bash
npm install
npm run seed   # サンプルデータ（部屋・プラン・オプション）を投入
npm run dev    # http://localhost:3000 で起動
```

2回目以降（パソコンの再起動後や、新しいバージョンに入れ替えたとき）：

```bash
npm install    # 新しいバージョンで依存パッケージが変わっていた場合のみ必要。念のため毎回実行してOK
npm run dev    # http://localhost:3000 で起動
```

`npm run seed` は毎回実行する必要はありません。データ（部屋・プラン・料金カレンダー・予約など）は
プロジェクトフォルダの外側、ホームディレクトリ配下の `modanica-data/data.json` に保存されるようにしているため、
新しいバージョンのzipに入れ替えても、これまで登録した設定や予約は消えずに引き継がれます。
（`npm run seed` を実行しても、既にデータが存在する場合は自動的にスキップされ、上書きされません。）

サンプルデータに戻してやり直したい場合だけ、`npm run seed:reset` を実行してください
（既存の予約・設定はすべて消えるので注意してください）。

### メール送信を有効にする（任意）

何もしなくてもアプリは動きますが、メールは実際には送信されず「ログモード」（`/admin/mail-log` に記録だけされる）
になります。実際にメールを送りたい場合は次の手順です。

1. [Resend](https://resend.com) にサインアップする（無料枠あり）
2. 送信元にしたいメールアドレス／ドメインをResend側で認証する
3. Resendの管理画面でAPIキーを発行する
4. プロジェクトのフォルダにある `.env.local.example` を同じ場所に `.env.local` という名前でコピーし、
   `RESEND_API_KEY` などの値を書き換える
5. `npm run dev` を再起動する

`.env.local` はデータと同様に個人設定なので、バージョンを入れ替える（新しいzipに差し替える）ときは
新しいフォルダにも同じ `.env.local` をコピーしてください（自動では引き継がれません）。

## ディレクトリ構成

```
app/                 画面・APIルート（Next.js App Router）
  plans/facility      施設利用プラン一覧
  plans/cafe          カフェ系プラン一覧
  plans/[id]          プラン詳細
  reserve/[id]        予約フォーム
  complete/[id]       予約完了ページ
  admin               予約管理（簡易版）
  api/plans           プラン取得API
  api/availability    空き状況・料金確認API
  api/reservations    予約作成・一覧・ステータス更新API
components/           画面部品（PlanCard, ReserveForm）
lib/
  store.js            データストア（JSONファイル）
  plans.js            プラン取得ロジック
  availability.js      重複予約チェックロジック
  pricing.js          曜日タイプ別の料金計算
  timeTemplates.js     プランごとの時間帯（IN/OUT・スロット・時間指定）の算出
  mailer.js           メール送信（Resend連携・未設定時はログモード）
  emailTemplates.js    予約受付・確定・キャンセル等のメール文面
scripts/seed.js       初期データ投入スクリプト
.env.local.example    メール送信設定のサンプル（コピーして .env.local を作る）
```

## 既知の注意点

- Next.js 14.2系はいくつかセキュリティアドバイザリが出ています。本番公開前に最新の安定版（15系/16系）への
  アップグレードを検討してください（`npm audit` で確認できます）。
- 予約の重複判定は「資源（部屋・BBQエリア・カフェ全体）が重なり、日時が重複するとき、どちらか一方でも
  排他的なプランなら競合とみなす」というルールです（設計書3.1・4章に対応）。カフェの部分利用同士（プラン7・8・9）
  は共存を許可しています。
